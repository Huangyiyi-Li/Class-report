## 一、背景

### 1.1 领导反馈四点
| # | 反馈 | 解码 |
| --- | --- | --- |
| 1 | 不同学科特点/要点没有区别 | 全部 Prompt 学科无关，语文数学输出一样 |
| 2 | 数据展示维度 | 维度太"平"，没有按受众分层 |
| 3 | 要考虑教师分层 | 静态分层 → 结果分层 → 个性化建议，三步走 |
| 4 | 问题分析 | 领导要的是"诊断书"（定位→归因→预判→验证），不是"体检报告" |

### 1.2 用户反馈关键信号
学校用户反馈**导师改进建议（Agent F）特别好**。

**结论**：产品核心价值 = "一位该学科的特级教师会怎么评这节课"。图表是论据，不是结论。

### 1.3 领导 AI 方案定位
领导用 AI 生成了完整产品方案（`AI评课产品方案.txt`），其中：

- **可直接用**：附录 A 通用评课维度表、A.2 学科维度、六维评分体系
- **需要补充**：学科差异化实现方式、维度受众分层、教师分层动态性、问题分析闭环、冷启动方案

## 二、架构设计

### 2.1 设计原则
1. **零侵入**：v1/v2 代码不改动，v3.0 全部放在独立文件夹
2. **配置驱动**：学科差异 = 配置文件，不是 27 套 Prompt
3. **参数化**：Prompt 模板只有一套，接收学科配置 + 课型配置作为参数
4. **产品核心是 Agent F**：学科感知的导师建议是最大价值点

## 四、核心模块设计

### 4.1 icas_subject_engine.py — 学科感知引擎
**职责**：

1. `load_subject_profile(subject_name)` — 加载学科配置
2. `load_lesson_type_config(lesson_type)` — 加载课型配置
3. `build_subject_aware_prompt_f(profile, lesson_type)` — 生成学科增强版 Agent F Prompt
4. `build_subject_dimensions_prompt(profile)` — 生成学科特有维度分析 Prompt
5. `build_problem_diagnosis_prompt(profile, lesson_type)` — 生成问题诊断四步法 Prompt
6. `analyze_with_subject(transcription, subject, lesson_type, base_data)` — 执行完整分析
**Agent F 重新设计**：

从"万能诊断书"变为"学科特级教师诊断"：

- 输入：转录文本 + 学科配置 + 课型配置 + v1/v2 分析数据
- 角色：该学科特级教师导师
- 输出：用学科语言、针对学科特点、可落地的诊断建议
- 内嵌问题诊断四步法：定位→归因→预判→验证

### 4.2 icas_teacher_tier.py — 教师分层
**三层分步**：

Step 1: 静态分层

- 维度：学科 × 年级 × 教龄
- 作用：在正确的人群中做对比
Step 2: 结果分层

- 输入：五维雷达 + 学科特有维度评分
- 输出：卓越(90+) / 成熟(75-89) / 成长(60-74) / 待提升(<60)
- 各档自动匹配不同建议策略
Step 3: 个性化建议

- 输入：分层结果 + 学科 + 薄弱项 + 纵向趋势
- 输出：针对性改进路径 + 推荐学习资源

### 4.3 icas_report_v3.py — 三视角报告
**教师视角**：

- 学科雷达 + 学科特有维度 + 微格切片 + 问题诊断 + 导师建议
- 核心：可操作性
**教研员视角**：

- 对标分析 + 同学科均值对比 + 纵向趋势 + 分层定位
- 核心：诊断准确性
**校长视角**：

- 教师分层地图 + 学科对比 + 异常预警 + 趋势总览 + 决策建议
- 核心：决策支撑

### 4.4 auto_analyze_v3.py — CLI 入口

```bash
# 基本用法（兼容 v2，走老流程 + v3 增强）
python auto_analyze_v3.py "目录路径" --subject 语文 --lesson-type 新课

# 完整参数
python auto_analyze_v3.py "目录路径" \
    --subject 数学 \
    --lesson-type 复习课 \
    --teacher "张老师" \
    --grade "三年级" \
    --experience 5 \
    --audience teacher \
    --school "濮东小学"

# 不传 subject → 走纯 v2 流程，兼容旧数据
python auto_analyze_v3.py "目录路径"

```

## 五、与 v1/v2 的兼容性
| 场景 | 行为 |
| --- | --- |
| 不传 --subject | 走 v2 流程，输出和原来一模一样 |
| 传 --subject 语文 | v2 分析 → v3 学科增强 → 三视角报告 |
| 已有 v2 缓存 | 复用 core_cache/extended_cache，只补跑 v3 增强部分 |
| v1/v2 命令 | 完全不受影响，独立运行 |
