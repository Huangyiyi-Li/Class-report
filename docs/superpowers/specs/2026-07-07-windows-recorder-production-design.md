# Windows 课堂录音采集客户端产品设计

- 状态：已确认
- 日期：2026-07-07
- 平台：Windows 10/11 x64

## 1. 目标

将现有录音 demo 建设为可正式安装、稳定录音、自动补传和持续维护的 Windows 客户端。

首版只解决四件事：

1. 用户可以自己完成设备绑定，不需要技术人员现场配置。
2. 程序启动后可按设置自动录音。
3. 断网、界面崩溃和突然断电时尽量不丢录音。
4. 音频按设备位置上传，供 PC 端选择日期和有效时段创建报告。

## 2. 首版范围

### 包含

- Windows 10/11 x64；
- 程序和数据存放在非系统盘；
- 开机自启设置；
- 启动后自动录音设置；
- 独立录音工作进程；
- 5 分钟音频分段；
- 本地可靠队列、断网补传；
- 微信扫码自助绑定；
- 班级教室和录播教室两类采集位置；
- 主窗口、托盘、悬浮球、设置和必要诊断；
- 安装包、基础自动化测试、Windows 真机测试和发布说明。

### 不包含

- 客户端读取课表或判断上下课；
- 客户端自动判断课程、教师和班级；
- 服务端远程下发录音策略；
- Windows 7/8；
- 绕过冰点或其他系统保护；
- 复杂设备监控平台和自动升级平台。

## 3. 平台与冰点

1. 程序、配置、音频、上传队列和日志全部位于非系统盘。
2. 启动时检查数据目录是否存在、可写且空间充足。
3. 数据盘不可用时禁止录音，不能改写到系统盘。
4. 客户端不尝试绕过冰点。
5. 开机启动项可能被冰点还原，需要通过解冻固化或白名单解决。
6. 客户端显示启动项的实际状态，不能仅显示用户开关值。

Windows 7 不纳入首版兼容。该风险写入部署说明，后续根据学校白板调研结果决定是否单独立项。

## 4. 运行设置

客户端提供两个独立开关：

### 开机自启

控制客户端是否随 Windows 启动。界面显示：

- 已开启并验证；
- 已设置但未验证；
- 启动项不存在或注册失败。

### 启动后自动录音

控制程序启动并通过检查后是否立即录音。

即使关闭开机自启，只要开启自动录音，用户手动打开程序后仍应自动开始录音。

自动录音开始前必须确认：

- 非系统盘可写；
- 磁盘空间充足；
- 麦克风可用；
- 设备已经绑定采集位置；
- 音频已经实际落盘。

网络不可用不阻止录音，只影响上传。

## 5. 技术结构

采用“Electron 桌面界面 + 独立录音工作进程”。

### Electron 桌面界面

负责：

- 主窗口、托盘和悬浮球；
- 首次绑定和设置；
- 展示录音、上传和设备状态；
- 用户开始、暂停、停止和补传操作。

界面不保存长时间音频。界面崩溃或重启时，录音工作进程继续运行。

### 录音工作进程

负责：

- 读取麦克风；
- 持续写入临时音频；
- 每 5 分钟生成一个上传分段；
- 发生异常后自动恢复；
- 向界面报告音量、录音状态和错误。

音频至少每 10 秒形成一个安全落盘点。进程崩溃或断电时，最多允许丢失 10 秒尚未落盘的音频。

### 本地队列与上传

1. 使用 SQLite 保存上传队列，不再直接覆盖 JSON。
2. 音频先落盘，再进入上传队列。
3. 上传和录音互不阻塞。
4. 断网后自动重试。
5. 单个失败分段不能阻塞其他分段。
6. 文件上传和音频信息登记均成功后，分段才算完成。

## 6. 音频规格

- 采样率：16 kHz；
- 单声道；
- 16 bit；
- 首选 Ogg Opus；
- 目标码率：32 kbps；
- 5 分钟一个上传分段；
- 编码失败时回退 WAV，优先保证录音可用。

## 7. 状态模型

客户端并行展示三类状态，不能互相覆盖。

### 录音状态

- 待机；
- 录音中；
- 已暂停；
- 无法录音。

### 上传状态

- 无待传；
- 上传中；
- 等待网络，显示待传数量；
- 部分失败，显示处理入口。

### 设备状态

- 正常；
- 启动项未验证；
- 麦克风不可用；
- 数据盘不可用；
- 磁盘空间不足；
- 尚未绑定。

“网络异常”不能替换“录音中”。每个错误都要说明录音是否安全以及用户需要做什么。

## 8. 自助绑定

### 前置条件

使用者必须先通过现有资料导入流程加入目标学校。普通教师、班主任或学校信息化管理员都可以完成绑定。账号可以属于多所学校。

### 流程

1. 未绑定客户端显示一次性二维码。
2. 用户微信扫码并登录小程序。
3. 系统读取账号已加入的学校。
4. 多学校账号明确选择目标学校。
5. 用户选择采集位置类型。
6. 用户匹配已有位置或按规则创建位置。
7. 确认设备、学校和采集位置。
8. 服务端保存绑定，客户端自动同步结果。
9. 客户端完成自检，并按设置进入自动录音或待机。

如果账号没有目标学校，不允许任意搜索绑定，提示先由学校管理员导入账号资料。

## 9. 采集位置

### 班级教室

- 必须关联系统已有班级和 `classId`；
- 用户从年级、班级中选择；
- 已有位置时直接匹配；
- 没有位置时基于该班级创建位置；
- 不允许自由输入班级名称替代班级 ID。

### 录播教室

- 不关联班级 ID；
- 用户可以选择同校已有录播教室；
- 用户可以输入名称新建；
- 出现同名或近似名称时优先提示使用已有位置。

客户端实际绑定：

`deviceId + schoolId + locationId`

## 10. 设备迁移与录音归属

设备更换采集位置时：

1. 关闭旧绑定；
2. 创建新绑定；
3. 绑定记录保存生效和失效时间；
4. 过去录音继续归属采集当时的位置。

上传音频至少包含：

- `deviceId`；
- `locationId`；
- 开始时间和结束时间；
- 分段序号；
- 音频格式和文件地址。

客户端不理解课表。PC 创建报告时按“设备位置 + 日期”选择录音，再选择有效开始和结束时间。

## 11. 必要故障处理

### 断网

继续录音并保存本地队列，网络恢复后自动补传。

### 界面崩溃

录音工作进程继续运行，界面重新启动后恢复状态。

### 录音进程崩溃或突然断电

下次启动恢复临时音频和上传队列；最大未落盘损失不超过 10 秒。

### 麦克风异常

立即停止显示“录音中”，持续尝试恢复，并记录中断时间。

### 磁盘不足

低于 5 GB 时告警。先清理超过保留期且已完成上传的文件，永不自动删除待传或失败文件。

### 单个队列项失败

隔离失败项，其他分段继续上传。

## 12. 本地保留

- 已完成上传和登记的音频默认保留 7 天；
- 待传和失败音频不自动删除；
- 日志默认保留 30 天；
- 支持打开数据目录和导出脱敏诊断包。

## 13. 必要安全要求

1. 正式源码和安装包不得包含测试学校、班级、账号或密码。
2. 开发、测试和生产配置分开。
3. 日志不得记录密码、令牌和 OSS 临时密钥。
4. Electron 保持 `contextIsolation: true`、`nodeIntegration: false`。
5. 正式安装包使用 Windows 代码签名证书。
6. 卸载或升级不得删除录音数据和待传队列。

## 14. 首版界面

只保留四个主要界面：

1. 首次绑定：二维码、绑定进度和失败处理；
2. 主状态：当前位置、录音状态、上传状态和设备异常；
3. 设置：两个运行开关、麦克风、数据目录、绑定信息和版本；
4. 诊断：队列数量、最近错误、磁盘和诊断包导出。

停止录音、解绑和迁移设备时，必须说明影响并要求用户确认。

## 15. 必要测试

### 自动化测试

- 录音与上传状态；
- SQLite 队列状态和失败隔离；
- 断网补传；
- 设备绑定和迁移历史；
- 配置保存和升级迁移；
- IPC 参数校验。

### Windows 真机测试

- Windows 10 和 Windows 11；
- 至少两种学校白板；
- 有冰点和无冰点环境；
- 集成麦克风和 USB 麦克风；
- 断网、断电、强杀进程、磁盘不足和麦克风断开；
- 安装、覆盖升级和卸载；
- 100%、125%、150% 系统缩放。

候选版本必须通过连续 72 小时录音测试后，才能进入学校试点。

## 17. 发布流程

1. 规格确认；
2. 分模块开发和自动化测试；
3. Windows 真机及 72 小时测试；
4. 选择 1–3 所学校试点；
5. 修复试点问题；
6. 签名正式发布。

需求完成的最低标准：代码、测试、错误处理、必要日志和相关文档同时完成。

## 18. 已知风险

### Windows 7

首版不兼容。试点前调研学校白板系统分布；如果占比较高，单独评估，不降低主版本安全基线。

### 冰点启动项

程序和数据可以放在非系统盘，但启动项仍可能被还原。需要真机验证解冻固化或白名单方案。

### 学校账号资料

用户未被导入目标学校时无法自助绑定。正式部署前必须先完成账号资料导入。

### 录播教室重名

同校可能创建重复位置。首版通过近似名称提示和优先匹配已有位置降低风险。
